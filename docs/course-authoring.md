# Systems X-Ray 课程编写规范

这份规范用来保证 Kafka、OpenSearch、Redis、PostgreSQL 以及未来的 JVM、Spring Boot、Kubernetes 课程看起来像同一套产品，也使用同一种学习方法。

## 1. 先定义课程主角

每门课只追踪一个可识别对象，并让它在所有页面保持同一身份：

- Kafka：`Event #A1024`
- OpenSearch：`Document #D2048`
- Redis：`Key session:user:9527`
- PostgreSQL：`Row orders.id=A1024`

主角的字段、版本、Offset、docID、LSN 等变化必须可以在前后页面对应，不能为了示意随意换数据。

## 2. 课程顺序

一门课优先按真实因果链组织，而不是按名词字典组织：

```text
业务意图
→ 客户端 API 与对象
→ 路由 / 协调节点
→ 进程与线程
→ 序列化 / 协议 / 网络
→ 内存结构
→ 文件与物理存储
→ 副本 / 可见性 / 一致性
→ 读取与业务处理
→ 故障、恢复与生产诊断
```

开始先给一张边界明确的全景图。后续每页只放大全景图中的一个位置，学员始终知道“我现在在哪里”。

## 3. 一页课件的内容契约

每页只回答一个问题，并至少包含：

1. **问题式标题**：例如“Replica 是 Primary 推过去，还是自己拉？”
2. **物理图或状态图**：必须表达组件、边界、方向或状态变化，不画无含义的装饰框。
3. **本页结论**：一句话回答标题。
4. **关键参数 / 事实**：只放真正改变行为的配置和边界条件。
5. **设计取舍**：同时写收益与代价。
6. **实现伪代码**：依据官方文档或源码语义提炼；不直接倾倒大段源码。

补充抽屉只放长配置表、故障推演、验证命令和依据链接，不重复主课件已经出现的内容。

## 4. 状态变化优先于静态框图

只要原理涉及变化，就使用下面一种表达：

### Before → Current → After

适合 Update、Delete、Merge、Rebalance、Leader 切换、Checkpoint：

```text
Before：旧版本仍可见
Current：新版本写入，旧版本打删除标记
After：Merge 只复制 live docs，旧字节才真正回收
```

### 同一物理图逐步高亮

适合一条消息穿过多个组件。保持拓扑不动，每页只移动主角、高亮当前组件，并淡化已经完成和尚未发生的路径。

### 关键状态量连续变化

适合 Offset、HW、LSO、LSN、xmin/xmax、VersionMap。状态量必须展示前值、触发事件和后值。

动画只用于说明变化，不自动播放长流程；同时支持 `prefers-reduced-motion`。

## 5. 什么时候必须拆成两页以上

出现任一情况就拆页：

- 标题实际包含两个不同问题。
- 图中同时出现超过 8 个需要解释的组件。
- 一页需要表达两个以上关键状态跳转。
- 伪代码超过约 12 行，或必须缩小到难以阅读。
- 解释需要内部滚动条。
- 配置、原理和故障案例互相争抢主视觉。

推荐拆法：

```text
第 1 页：路径与参与者
第 2 页：内部状态怎么变化
第 3 页：成功条件、一致性边界和失败分支
第 4 页：生产配置与 trade-off
```

## 6. 视口与交互

- 课程主画面必须在常见桌面视口内完整显示，禁止主区域内部滚动。
- 底部固定为：上一页 / 页码与主线提示 / 下一页。
- `←`、`→` 支持翻页；Hash 可以直接定位并刷新恢复。
- 点击图中组件只展示该组件的额外信息，不能让学员失去当前页面位置。
- 手机端可以减少辅助文字，但不能隐藏标题、本页结论和前后翻页。
- 所有交互必须有键盘焦点和可读名称。

## 7. 视觉一致性

- 使用统一的课件框架：顶栏、16:9 主画布、底部四栏讲义、翻页区。
- 一个课程只使用一个主强调色；红色仅表示故障或危险，绿色仅表示成功或可用。
- 物理边界使用实线，逻辑关系使用虚线，数据流使用带方向箭头的线。
- 同类组件保持同一形状；颜色不能成为唯一的信息编码。
- 大标题负责提出问题，图负责解释，底栏负责总结；三处不要重复同一句话。

## 8. 技术准确性

- 优先依据对应版本的官方文档、协议说明和源码行为。
- 页面结论必须注明适用边界，例如版本、配置模式、经典协议或新协议。
- 伪代码表达决策顺序和状态变化，不伪装成可编译源码。
- 对“写成功”“持久化”“可见”“提交”“业务完成”等相近概念必须分别定义。
- 高性能、高可用和一致性的结论必须带上失效条件与资源代价。

- [ ] 每页只有一个问题。
- [ ] 每个箭头都能回答“谁主动、传什么、什么时候完成”。
- [ ] 每个成功状态都有明确判定条件。
- [ ] 所有关键状态变化都有前值和后值。
- [ ] 没有为塞内容而缩字或增加主画布滚动条。
- [ ] 复杂主题已经拆成连续的 2–4 页。
